## Decisions made

**CSS animations over three.js** — for the hero slide-in. three.js (~150KB WebGL) is wrong for a 2D slide; CSS keyframes are 0KB, GPU-accelerated, accessible. Reversible: trivially.

**Keyless Google Maps embeds** (`output=embed`) — used on About and the service-area section. No API key to configure or leak. Tradeoff: **cannot draw a real radius circle or custom map style** — the dashed 20-mile ring is a decorative CSS overlay, not geo-accurate, and drifts with viewport width. A true circle/marker/styled map needs the Google Maps JS API + a referrer-restricted `NEXT_PUBLIC_` key.

**mailto contact form** — Phase 1 has no backend/Resend/Turnstile yet. The form opens the visitor's mail client to the confirmed address. Swappable for a real server action later (one component).

**Brand green over mockup red** — the Landfills section mockup used red; kept the site's green for consistency (red is only the "danger" token).

**Kept Herriman, not Holladay** — some later mockups (service-area, reviews) referenced Holladay as the center/city. Kept **Herriman** to match the earlier explicit instruction + confirmed config. Flagged for confirmation.

## Gotchas encountered

- **`.next` dev cache corruption** — running `rm -rf .next/dev` while `next dev` was live left a half-written Turbopack cache → `Cannot find module '[turbopack]_runtime.js'` + LMDB "write batch already active" and 500s. Fix: stop the dev server first, `rm -rf .next`, restart. Never delete the cache while the server is running.
- **CSS descendant-selector dimming icons** — `.reviewTrustItem span` and `.haulPoint span` (specificity 0,1,1) also matched the icon-wrapper `<span>`, recoloring white/green icons to muted grey ("missing icons"). Fixed by scoping to `.reviewTrustItem > div span` / `.haulPoint > div span`.
- **SCSS media-query brace slip** — inserting rules near the end of the `@media (max-width:62rem)` block accidentally closed it early, pushing tablet rules into a stray 44rem block. Verify brace balance after inserting into media blocks.
- **Two lockfiles warning** (cosmetic, unresolved) — Next detects both `~/package-lock.json` and the project's; harmless but noisy. Fix later by removing the stray home-dir lockfile or setting `turbopack.root`.
